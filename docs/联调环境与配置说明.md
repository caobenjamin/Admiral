## 二、配置信息初始化位置

### 1. 服务端配置（必做）

| 配置项 | 位置 | 说明 |
|--------|------|------|
| **环境变量 / 敏感项** | **项目根目录的 `.env` 文件** | 首次：`cp .env.example .env`，再编辑 `.env` |
| **非敏感配置** | `crates/admiral-server/config/` | 已有 `default.toml`、`development.toml`、`production.toml`，一般无需改 |
| **配置目录解析** | 自动 | 在仓库根执行 `cargo run -p admiral-server` 时，会使用 `crates/admiral-server/config`；也可设置 `ADMIRAL_CONFIG_DIR` 指向自定义目录 |

**.env 中必须填写的项（联调最少）：**

- `ADMIRAL_DATABASE_URL` — PostgreSQL 连接串（见上方数据库说明）
- `ADMIRAL_JWT_PRIVATE_KEY_PATH`、`ADMIRAL_JWT_PUBLIC_KEY_PATH` — 指向你生成的 PEM 文件路径（见下）
- （可选）`ADMIRAL_TOKEN_ENCRYPTION_KEY` — 32 字节 hex，B 站 OAuth Token 加密用；不配则 B 站相关功能不可用
- （可选）B 站 OAuth：`ADMIRAL_BILI_APP_ID`、`ADMIRAL_BILI_APP_SECRET`、`ADMIRAL_BILI_CALLBACK_URL`
- （可选）LLM：`ADMIRAL_LLM_DEFAULT_PROVIDER`、`ADMIRAL_DEEPSEEK_API_KEY` 等

**JWT 密钥生成（在项目根或你打算放密钥的目录执行）：**

```bash
mkdir -p keys
openssl genpkey -algorithm RSA -out keys/private.pem -pkeyopt rsa_keygen_bits:2048
openssl rsa -in keys/private.pem -pubout -out keys/public.pem
```

若密钥不在项目根下的 `./keys/`，则在 `.env` 中设置 `ADMIRAL_JWT_PRIVATE_KEY_PATH` 与 `ADMIRAL_JWT_PUBLIC_KEY_PATH` 为绝对路径或相对路径。

**Token 加密密钥生成（可选，用于 B 站 OAuth）：**

```bash
openssl rand -hex 32
```

将输出填入 `.env` 的 `ADMIRAL_TOKEN_ENCRYPTION_KEY`。

### 2. 客户端配置（可选）

| 配置项 | 位置 | 说明 |
|--------|------|------|
| **API 地址** | 环境变量 `ADMIRAL_API_BASE_URL` | 不设则默认 `http://127.0.0.1:8080`，联调一般不用改 |
| **凭证文件路径** | 环境变量 `ADMIRAL_CREDENTIAL_FILE` | 不设则默认 `credentials.json`（相对 `crates/admiral-client` 运行目录） |

客户端在 `crates/admiral-client` 下执行 `cargo tauri dev` 时，工作目录通常为该目录，因此默认会在 `crates/admiral-client/credentials.json` 读写登录后的 token。**无需事先创建该文件**，登录成功后会自动生成。

若希望把凭证放在别处，可在启动前设置：

```bash
export ADMIRAL_CREDENTIAL_FILE=/path/to/credentials.json
cargo tauri dev
```

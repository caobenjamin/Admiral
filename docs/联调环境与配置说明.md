# 联调环境与配置说明

## 联调模式

**服务端**：统一在**远端服务器**部署并运行，本地不部署、不运行服务端，仅做代码编辑。  
**客户端**：本地运行，通过 `ADMIRAL_API_BASE_URL` 连接远端服务端 API 进行联调。

---

## 一、本地环境依赖

| 依赖 | 要求 | 说明 |
|------|------|------|
| **Rust** | 1.85+ (2024 edition) | 用于编译客户端 |
| **Node.js** | 20+ | 客户端 UI 构建 |
| **npm** | - | 客户端 UI 依赖 |
| **OpenSSL** | - | 可选，用于生成密钥等 |
| **客户端 UI 依赖** | `crates/admiral-client/ui` | 执行 `npm install` 后可直接 `cargo tauri dev` |

**说明**：本地**不需要** Docker、PostgreSQL，数据库与服务端均在远端服务器运行。

---

## 二、本地配置

### 1. 客户端配置

| 配置项 | 说明 |
|--------|------|
| **ADMIRAL_API_BASE_URL** | **必设**，远端服务端 API 的 HTTPS 地址（无路径、无末尾斜杠），例如 `https://admiral.example.com` |
| **ADMIRAL_CREDENTIAL_FILE** | 可选，凭证文件路径，默认 `credentials.json` |

### 2. 启动客户端

```bash
# 在仓库根目录
export ADMIRAL_API_BASE_URL=https://admiral.example.com   # 替换为你的服务端地址
cargo tauri dev
```

或通过配置文件（如 `crates/admiral-client/client.json`）指定 API 地址，具体参见客户端配置实现。

### 3. 凭证文件

登录成功后，客户端会在工作目录下自动生成 `credentials.json` 保存 token，**无需事先创建**。

## 四、联调前自检清单

1. [ ] 远端服务端已部署并正常运行，`https://你的域名/health` 返回 200
2. [ ] 本地已设置 `ADMIRAL_API_BASE_URL` 为远端服务端地址
3. [ ] 在仓库根目录执行 `cargo tauri dev` 能启动客户端并打开登录页
4. [ ] （B 站 OAuth）B 站开放平台回调地址已配置为 `https://你的域名/api/v1/oauth/bilibili/callback`

完成以上后即可开始联调（登录、注册、B 站授权、MAPI 调试、LLM 对话等）。

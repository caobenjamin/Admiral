# 知识库初始化

知识库用于 Agent 对话时的 RAG 检索：用户发送消息后，服务端会按关键词做全文检索，将相关片段注入上下文，供 LLM 参考。本文说明如何初始化与更新知识库内容。

---

## 一、数据从哪里来

- **存储**：服务端 PostgreSQL 表 `knowledge_chunks`（由迁移自动创建）。
- **内容来源**：服务端机器上的 **Markdown（.md）文件**，通过「入库（ingest）」写入数据库。
- **检索**：客户端 Agent 发送消息时，会调用 `POST /api/v1/knowledge/query`，服务端用 PostgreSQL 全文检索（`to_tsvector` / `plainto_tsquery`）返回最相关的若干片段。

---

## 二、初始化步骤

### 1. 在服务端准备知识目录

在**运行 Admiral 服务端的机器**上，选一个目录存放 Markdown 文件，例如：

```text
/path/to/admiral-server/knowledge/
  bilibili_ad_basics.md    # B站广告基础
  mapi_reference.md        # MAPI 接口说明
  best_practices.md        # 投放最佳实践
  troubleshooting.md       # 常见问题
```

每个文件为普通 Markdown，可按 `#` / `##` 分章节书写；入库时会按标题和段落切分为多个 chunk，便于检索。

### 2. 配置知识目录路径（可选）

- **默认**：服务端进程的**当前工作目录**下的 `knowledge` 子目录（即 `./knowledge`）。
- **自定义**：设置环境变量 **`ADMIRAL_KNOWLEDGE_DIR`** 为绝对或相对路径，例如：
  ```bash
  export ADMIRAL_KNOWLEDGE_DIR=/opt/admiral/knowledge
  ```

### 3. 执行入库（需要管理员权限）

入库通过**管理员 API** 触发，且需要**管理员账号**的 JWT。

**方式 A：调用 API（推荐）**

```bash
# 使用管理员 token
export TOKEN="你的管理员 JWT access_token"

# 使用默认目录 ./knowledge（或 ADMIRAL_KNOWLEDGE_DIR）
curl -X POST "https://你的域名/api/v1/admin/knowledge/ingest" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json"

# 或指定目录（覆盖默认与环境变量）
curl -X POST "https://你的域名/api/v1/admin/knowledge/ingest" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"dir": "/opt/admiral/knowledge"}'
```

成功时返回示例：

```json
{ "chunks_inserted": 42 }
```

表示本次写入了 42 个片段。

**方式 B：不传 body**

不传 body 或传 `{}` 时，使用默认目录或 `ADMIRAL_KNOWLEDGE_DIR`。

### 4. 入库规则说明

- 只扫描指定目录下的 **`.md`** 文件，其他格式忽略。
- **切分策略**：按 Markdown 的 `#` / `##` 标题分段，单段超过约 2000 字符会再按长度切块。
- **同一文件重复入库**：会先删除该文件对应的旧 chunk，再插入新 chunk，即「按文件覆盖」。

---

## 三、更新知识库

- **新增/修改 .md 文件**后，再次调用 **`POST /api/v1/admin/knowledge/ingest`**（同上）。
- 同一 `source_file` 会先删后插，因此该文件会以最新内容为准；其他文件不受影响。
- 若希望全量重建，可对同一目录再次执行一次 ingest，所有该目录下的 .md 都会按当前内容重新入库。

---

## 四、自检

1. **表是否就绪**：服务端启动时会跑迁移，应已存在 `knowledge_chunks` 表。
2. **目录是否存在**：确保 `./knowledge` 或 `ADMIRAL_KNOWLEDGE_DIR` 指向的目录存在，且内含 .md 文件。
3. **权限**：调用 ingest 的账号需为**管理员**（`role = admin`）。
4. **检索是否生效**：在客户端与 Agent 对话，问一些知识库中已有的内容，若配置正确，Agent 会引用相关片段（取决于前端/Agent 是否展示来源）。

---

## 五、相关 API

| 方法 | 路径 | 说明 | 认证 |
|------|------|------|------|
| POST | `/api/v1/knowledge/query` | 查询知识片段（body: `query`, `top_k`），供 Agent 使用 | JWT |
| POST | `/api/v1/admin/knowledge/ingest` | 从指定目录入库 .md 到知识库 | JWT（管理员） |

环境变量：

| 变量 | 说明 |
|------|------|
| `ADMIRAL_KNOWLEDGE_DIR` | 知识库 Markdown 根目录（可选，默认 `./knowledge`） |

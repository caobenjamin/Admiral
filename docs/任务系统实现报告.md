# Admiral 任务系统实现报告

本文档描述基于 [prd/6th-任务系统.md](../prd/6th-任务系统.md) 完成的**任务系统**具体实现，架构参考 OpenClaw 的 Agent 与任务模式。

---

## 一、整体架构

任务系统由七大模块组成：

| 模块 | 位置 | 职责 |
|------|------|------|
| **记忆系统** | 客户端 `agent/memory.rs` | Markdown 文件存储 + SQLite FTS5 混合检索 |
| **知识体系** | 服务端 `service/knowledge_service.rs` | 知识查询 API（PostgreSQL 全文检索，可扩展 pgvector） |
| **Skill 工具体系** | 客户端 `skill/` | skill.toml 解析、注册、校验、执行（MAPI/本地），含 per-account 速率限制 |
| **Agent Runtime** | 客户端 `agent/` | Profile、Context（含 TaskSpec 注入）、ReAct 循环、LLM tool_call 全流程，支持流式 SSE |
| **规格更新器** | 客户端 `agent/spec_updater.rs` | 对话后自动提取结构化信息，更新 TASK_SPEC.md，评估完整度并推进状态 |
| **任务引擎** | 客户端 `task/engine.rs` | 对话驱动状态机、DryRun/TestRun/生产执行、统一生命周期管理 |
| **任务规格** | 客户端 `task/spec.rs` | TaskSpec 结构体、Markdown 序列化/反序列化 |
| **完整度评估** | 客户端 `task/completeness.rs` | 规则引擎：检查必需/推荐/可选项，输出 CompletenessLevel |
| **执行报告** | 客户端 `task/report.rs` | 执行后自动生成结构化 Markdown 报告 |
| **任务执行器** | 客户端 `task/executor.rs` | StepContext 数据管道、ForEach 批量、条件执行、重试退避、进度事件 |
| **定时调度器** | 客户端 `task/scheduler.rs` | Heartbeat / Cron 任务定时触发（查询 Active 状态任务） |
| **数据持久化** | 客户端 `db/` | SQLite 表：tasks、task_runs、conversations、memory_entries、logs |

数据流概览：

- **用户消息** → Context Assembler → ReAct Loop（LLM + tool_call）→ Skill Executor（MAPI/本地）→ 结果回传
- **任务创建** → TaskEngine 持久化 → 状态机流转 → DryRun/TestRun/Production 执行
- **定时触发** → Scheduler 检测到期任务 → TaskEngine.run → 自动执行

## 二、基础类型与数据层

### 2.1 admiral-types

**`crates/admiral-types/src/skill.rs`**

- `SkillCategory`：Semantic / Tools / Mapi
- `RiskLevel`：Low / Medium / High / Critical
- `SkillApi`：method、path、rate_limit
- `SkillInputDef`：required / optional 参数名
- `SkillLlmTool`：name、description、parameters_schema（供 LLM function calling）
- `SkillDefinition`：完整技能定义（id、name、category、platform、risk、api、input、llm_tool）
- `SkillCall`：技能调用（skill_id、params、account_id、dry_run）
- `SkillResult`：执行结果（success、data、error）

**`crates/admiral-types/src/task.rs`**

- `TaskType`：Instant / Cron / Heartbeat
- `TaskCategory`：DataFetch / Create / Update / Mixed
- `TaskStatus`（对话驱动模型）：Draft → Exploring → Configuring → Testing → Ready → Active / Running / WaitingForApproval / Paused / Completed / Failed / Cancelled
- `CompletenessLevel`：Incomplete / Partial / Sufficient / Complete（任务信息完整度评估）
- `TaskTrigger`：cron_expression、heartbeat_condition、next_run_at
- `RetryPolicy`：max_retries、backoff_ms、backoff_multiplier（指数退避）
- `StepMode`：Single / ForEach（source、item_binding、max_concurrency）
- `StepActionOnFalse`：Skip / Fail
- `TaskStep`：seq、skill_id、params、depends_on、description、**output_key**、**param_bindings**、**mode**、**condition**、**on_condition_false**、**retry_policy**
- `TaskPlan`：steps、risk_level
- `Task`：id、name、description、task_type、task_category、status、**completeness**、plan、platform、account_ids、trigger
- `RunType` / `RunStatus` / `StepResult` / `TaskRun`：执行记录与步骤结果
- `TaskProgress`：StepStarted / StepCompleted / StepSkipped / BatchProgress / TaskCompleted
- `PendingApproval`：操作审批信息
- `OperationPermission`：自动审批规则

### 2.2 SQLite 数据表

- **tasks**：id、name、description、task_type、status、**completeness**、**spec_version**、plan(JSON)、platform、account_ids(JSON)、trigger 相关字段
- **task_runs**：id、task_id、run_type、status、step_results(JSON)、error、resume_from_step、completed_steps
- **conversations**：id、task_id、session_id、role、content、tool_calls、timestamp
- **memory_entries**：id、key、content、category、source_file（供 FTS5 扩展）
- **logs**：request_id、task_id、skill_id、level、message、details、timestamp
- **operation_permissions**：scope_type、scope_id、operation、auto_approve
- **pending_approvals**：task_id、run_id、step_seq、skill_id、operation

## 三、Skill 系统

### 3.1 目录与 skill.toml

Skill 按目录组织在 `crates/admiral-client/skills/`：

```
skills/
  mapi/bilibili/get_account_list/skill.toml
  mapi/bilibili/get_account_balance/skill.toml
  tools/excel_export/skill.toml
  semantic/intent_parser/skill.toml
```

### 3.2 模块职责

| 模块 | 职责 |
|------|------|
| **loader.rs** | 递归扫描 skills 目录，解析 skill.toml 为 `SkillDefinition` |
| **registry.rs** | `SkillRegistry`（`RwLock<HashMap>`），提供 `get`/`list`/`build_llm_tools` |
| **validator.rs** | 校验 `SkillCall` 参数完整性（必填字段、account_id 等） |
| **executor.rs** | 按 category 分发执行；MAPI 类走 `api_client.mapi_proxy`；含 **per-account 速率限制**（governor，默认 10 req/s） |

### 3.3 速率限制

`SkillExecutor` 内置基于 `governor` 的 per-account 速率限制器（`DashMap<i64, Arc<MapiLimiter>>`），每个广告账户独立限流，避免触发平台 API 限制。

## 四、Agent Runtime

### 4.1 Agent Profile（profile.rs）

- 从 `admiral_data_dir()/agent_profile.toml` 加载人格配置
- 缺省使用内置默认 profile
- `build_system_prompt()` 生成系统提示

### 4.2 Context Assembler（context.rs）

- `build(session, knowledge_snippets)` 组装完整上下文
  - System：Profile + User Memory + Task Memory + Knowledge 片段 + Available Tools 提示
  - Messages：历史对话（当前用户消息已在 session.messages 中）
- 返回 OpenAI messages 格式的 JSON 数组

### 4.3 ReAct 循环（runtime.rs）

- `process_message(session, user_message, access_token)`：非流式
- `process_message_stream(session, user_message, access_token, tx)`：流式 SSE
- 流程：Knowledge 检索 → 上下文组装 → LLM 调用 → tool_calls 执行 → 循环至完成
- SSE 解析已提取为独立的 `process_sse_buffer` 函数

### 4.4 记忆系统

- **路径**：`~/.admiral/memory/USER_MEMORY.md`、`daily/YYYY-MM-DD.md`、`tasks/{task_id}/TASK_MEMORY.md`
- **MemoryStore**：读写用户/任务/每日记忆，SQLite FTS5 全文检索
- **memory_updater**：对话结束后异步提取偏好/事实，更新用户/任务记忆

## 五、任务引擎

### 5.1 状态机（state_machine.rs）

- `can_transition(from, to, task_type)` / `transition(from, to, task_type)`
- Cron / Heartbeat 任务成功后自动回到 Scheduled

### 5.2 Task Engine（engine.rs）

- `TaskEngine`：持有 `SkillRegistry` + `SkillExecutor`
- 公开方法：`create_task`、`save_task`、`get_task`、`delete_task`、`list_tasks`、`transition_to`
- `run(task, run_type, access_token, progress_tx)`：统一入口
- `resume_run(task, from_step, run_type, access_token, progress_tx)`：断点续执行
- 内部通过 `execute_and_finalize` 统一处理执行 → 持久化 → 状态转换

### 5.3 Task Executor（executor.rs）

执行器是任务系统的核心，实现了完整的步骤执行管道：

#### StepContext 数据管道

```rust
pub struct StepContext {
    data: HashMap<String, serde_json::Value>,
}
```

- 步骤可通过 `output_key` 将输出存入上下文（如 `"account_list"`）
- 后续步骤通过 `param_bindings` 引用上下文数据（如 `"$.step_1.records[0].account_id"`）
- 支持 JSONPath 风格的嵌套访问与数组索引

#### 条件执行

步骤可设置 `condition` 表达式（如 `"$.step_2.total > 1000"`），支持：

- 比较运算符：`>`、`<`、`>=`、`<=`、`==`、`!=`
- 数值与字符串比较
- `on_condition_false`：`Skip`（跳过并继续）或 `Fail`（中止任务）

#### ForEach 批量执行

```rust
StepMode::ForEach {
    source: "$.step_1.records",      // 上下文中的列表
    item_binding: "current_account",  // 每项绑定的变量名
    max_concurrency: 5,               // 并发控制
}
```

- 通过 tokio Semaphore 控制并发度
- 每项独立执行并汇总结果（batch_succeeded / batch_failed）
- 部分成功时继续执行后续步骤

#### 重试退避

```rust
RetryPolicy {
    max_retries: 3,
    backoff_ms: 1000,
    backoff_multiplier: 2.0,
}
```

- `execute_with_retry` 在失败时指数退避重试
- 日志记录每次重试尝试

#### 操作权限审批

- `classify_operation(skill_id)` 按 verb 后缀分类：Read / Write / Dangerous
- `is_auto_approved(task, skill_id)` 检查权限白名单
- 未授权的写操作暂停执行，等待用户审批后 resume

#### 实时进度事件

通过 `mpsc::Sender<TaskProgress>` 推送：

- `StepStarted { step_seq, total_steps }`
- `StepCompleted { step_seq, success }`
- `StepSkipped { step_seq, reason }`
- `BatchProgress { step_seq, completed, total }`
- `TaskCompleted { status }`

Tauri 侧通过 `spawn_progress_forwarder` 将事件转发为 `task-progress` 前端事件。

### 5.4 Scheduler（scheduler.rs）

- 每 30 秒检查到期的 Heartbeat 和 Cron 任务
- Heartbeat 任务：检查 `next_run_at` 是否已过期
- Cron 任务：当前依赖预计算的 `next_run_at`（cron 表达式解析待接入 `tokio-cron-scheduler`）
- 到期任务通过回调触发 `TaskEngine.run`
- 支持 `set_running(bool)` 控制调度器启停

### 5.5 Tauri 桥接

- **AppState**：持有 `TaskEngine`、`AgentRuntime`、`Scheduler`
- **会话管理**：`load_session` / `persist_new_messages` / `spawn_memory_update` 三个辅助函数统一处理会话加载、消息持久化、异步记忆更新
- **进度转发**：`spawn_progress_forwarder` 将 `TaskProgress` 事件桥接到 Tauri 前端事件

## 九、后续可扩展项

- **Knowledge RAG 增强**：接入 pgvector + embedding API 提升语义检索精度
- **Cron 表达式解析**：接入 `tokio-cron-scheduler` 实现真正的 cron 调度（当前依赖预计算 `next_run_at`）
- **步骤依赖 DAG**：`TaskStep.depends_on` 已在类型中定义，执行器可扩展为并行 DAG 执行
- **Heartbeat 配置 UI**：前端配置 heartbeat interval、active_hours、suppress 条件
- **WebSocket 通知**：替代轮询的实时任务状态推送

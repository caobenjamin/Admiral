# 开始运行：服务端在远端、客户端在本机

本文说明在**服务端部署在云服务器、本机只运行客户端**的前提下，需要做哪些准备与初始化，才能正常启动并使用（含登录、OAuth、任务系统、Agent 对话）。

---

## 一、总体流程

1. **远端**：准备服务器 → 安装 PostgreSQL → 配置服务端环境变量并启动 → 确认健康检查通过  
2. **本机**：安装 Rust / Node → 配置客户端环境变量 → 启动客户端 → 注册/登录  
3. **可选**：B 站 OAuth（需 HTTPS 回调）、LLM 对话与任务/Agent 所需的服务端配置  

**无需事先在客户端创建**：凭证文件（登录后自动生成）、本地 SQLite 库、记忆目录（首次使用时自动创建）。

---

## 二、远端服务端：需要初始化的内容

### 2.1 环境与依赖

- 一台有公网 IP 的云服务器（或内网 + 端口转发）
- 域名解析到该服务器（用于 HTTPS 与 B 站 OAuth 回调）
- 安装 **PostgreSQL**（若尚未安装）
- 使用 **Nginx / Caddy** 等做 HTTPS 终结并反向代理到 Admiral 后端

### 2.2 数据库

- 创建数据库与用户，例如：
  ```bash
  sudo -u postgres createuser -P admiral
  sudo -u postgres createdb -O admiral admiral
  ```
- 得到连接串，例如：`postgres://admiral:你的密码@localhost:5432/admiral`

服务端启动时会**自动执行 SeaORM 迁移**，无需手动跑迁移脚本（只要 `ADMIRAL_DATABASE_URL` 正确）。

### 2.3 服务端环境变量（.env）

在服务器上项目根目录（或运行目录）创建 `.env` 文件。**必配与常用项**如下：

| 变量 | 说明 | 示例 |
|------|------|------|
| `ADMIRAL_DATABASE_URL` | PostgreSQL 连接串 | `postgres://admiral:密码@localhost:5432/admiral` |
| `ADMIRAL_JWT_PRIVATE_KEY_PATH` | JWT 私钥路径 | `./keys/private.pem` |
| `ADMIRAL_JWT_PUBLIC_KEY_PATH` | JWT 公钥路径 | `./keys/public.pem` |
| `ADMIRAL_TOKEN_ENCRYPTION_KEY` | Token 加密密钥（32 字节 hex） | 运行 `openssl rand -hex 32` 得到 |
| `ADMIRAL_BILI_CALLBACK_URL` | B 站 OAuth 回调（必须 HTTPS） | `https://你的域名/api/v1/oauth/bilibili/callback` |
| `ADMIRAL_BILI_APP_ID` / `ADMIRAL_BILI_APP_SECRET` | B 站应用密钥 | 在 B 站开放平台申请 |
| `ADMIRAL_SERVER_HOST` | 监听地址（前有反向代理时用 127.0.0.1） | `127.0.0.1` |
| `ADMIRAL_SERVER_PORT` | 监听端口 | `8080` |
| `ADMIRAL_DEEPSEEK_API_KEY` | DeepSeek API Key（用于 LLM/Agent） | 在 DeepSeek 控制台获取 |
| `ADMIRAL_LOG_LEVEL` | 日志级别 | `info` 或 `debug` |

**JWT 密钥生成**（在服务器上执行一次）：

```bash
mkdir -p keys
openssl genpkey -algorithm RSA -out keys/private.pem -pkeyopt rsa_keygen_bits:2048
openssl rsa -in keys/private.pem -pubout -out keys/public.pem
```

**Token 加密密钥**：`openssl rand -hex 32`，将输出填入 `ADMIRAL_TOKEN_ENCRYPTION_KEY`。

完整变量说明见仓库根目录 [.env.example](../.env.example)。

### 2.4 B 站 OAuth（若要用 B 站授权与 MAPI）

1. 在 [B 站开放平台](https://open.bilibili.com/) 创建应用，拿到 **APP_ID**、**APP_SECRET**。  
2. 在应用后台配置「授权回调页」为：`https://你的域名/api/v1/oauth/bilibili/callback`（与 `.env` 中 `ADMIRAL_BILI_CALLBACK_URL` 完全一致）。  
3. 若暂不做 B 站授权，可不配 B 站相关变量，仅无法使用 MAPI 与绑定广告账户。

### 2.5 启动服务端

```bash
# 在服务器上，项目根目录
cd /path/to/Admiral
source .env   # 或 export $(grep -v '^#' .env | xargs)
cargo run -p admiral-server
# 或生产环境：用 systemd / supervisor 托管，见 docs/部署到GCP-从零到运行.md
```

确认：`curl -I https://你的域名/health` 返回 **200**。

## 三、本机客户端：需要初始化的内容

### 3.1 环境依赖

- **Rust** 1.85+（2024 edition）  
- **Node.js** 20+（用于构建前端）  
- 本机**不需要**安装 PostgreSQL、Docker；数据库在远端。

### 3.2 客户端环境变量

| 变量 | 说明 |
|------|------|
| **ADMIRAL_API_BASE_URL** | **必设**。远端服务端的 HTTPS 地址（无路径、无末尾斜杠），例如 `https://api.yourdomain.com` |
| **ADMIRAL_CREDENTIAL_FILE** | 可选。凭证文件路径，默认当前目录下的 `credentials.json` |

示例（在仓库根目录执行前）：

```bash
export ADMIRAL_API_BASE_URL=https://api.yourdomain.com
```

### 3.3 无需事先创建的内容

- **凭证文件**：首次登录成功后会由客户端自动生成（默认 `credentials.json`），无需手动创建。  
- **本地 SQLite**：客户端首次启动时会执行迁移，在 `~/.local/share/admiral/admiral.db`（Linux）或系统对应数据目录下自动创建库和表（tasks、task_runs、conversations 等）。  
- **记忆目录**：`~/.local/share/admiral/memory/` 及子目录在首次使用 Agent 记忆功能时自动创建。  
- **Agent 配置**：未放置 `agent_profile.toml` 时使用内置默认人格，无需初始化。  
- **Skill**：默认从客户端内置的 `skills/` 目录加载，无需拷贝。

### 3.4 启动客户端

在**仓库根目录**执行：

```bash
export ADMIRAL_API_BASE_URL=https://api.yourdomain.com   # 替换为你的服务端地址
cargo tauri dev
```

首次会编译并拉取前端依赖；完成后会打开桌面窗口，进入登录/注册页。

### 3.5 首次使用

1. 若尚无账号：在客户端完成**注册**（需有效的邀请码，由管理员在服务端创建）。  
2. **登录**成功后，凭证会写入本机（默认 `credentials.json`），之后可正常使用。  
3. 需要 B 站广告能力时：在客户端内进入「设置 → 平台授权」完成 B 站 OAuth；回调会跳到**远端**的 HTTPS 地址，由服务端处理。  
4. 首页可创建任务、使用 Agent 对话；任务数据保存在本机 SQLite，对话与 MAPI 请求走远端服务端。

## 四、自检清单（按顺序核对）

**远端服务端**

- [ ] PostgreSQL 已安装并已创建数据库/用户，`ADMIRAL_DATABASE_URL` 已配置  
- [ ] 已生成 JWT 密钥（`keys/private.pem`、`keys/public.pem`）并写入 `.env` 路径  
- [ ] 已生成并填写 `ADMIRAL_TOKEN_ENCRYPTION_KEY`（32 字节 hex）  
- [ ] 若用 B 站 OAuth：已配置 `ADMIRAL_BILI_CALLBACK_URL`、`ADMIRAL_BILI_APP_ID`、`ADMIRAL_BILI_APP_SECRET`，且 B 站开放平台回调页与 `ADMIRAL_BILI_CALLBACK_URL` 一致  
- [ ] 若用 LLM/Agent：已配置 `ADMIRAL_DEEPSEEK_API_KEY`  
- [ ] 反向代理（Nginx 等）已配置 HTTPS 并转发到 Admiral 端口  
- [ ] `curl -I https://你的域名/health` 返回 200  
- [ ] 服务端进程已启动（如 `cargo run -p admiral-server` 或 systemd）

**本机客户端**

- [ ] 已设置 `ADMIRAL_API_BASE_URL=https://你的域名`（无路径、无末尾斜杠）  
- [ ] 在仓库根目录执行 `cargo tauri dev` 能启动并打开登录页  
- [ ] 能完成注册/登录（凭证自动生成）  
- [ ] （可选）在设置中完成 B 站授权后，可使用 MAPI 与任务/Agent 中依赖 MAPI 的能力

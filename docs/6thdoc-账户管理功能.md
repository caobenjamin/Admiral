
我们来重新写下“媒体账户”这个板块。

首先，把他的名字改为“授权管理”，点击下拉展开媒体平台，当前只有一个 B站，未来会继续迭代其他媒体。

点击B站tab，将展开B站的tab。

tab共有以下部分组成。

上方是搜索和筛选框，允许进行账户名称的多选搜索和账户ID的精确匹配搜索。

在搜索和筛选框右侧，

有一个“新增账户”按钮，点击下拉列表，展示已授权的BID和user_name。点击任意一个BID时，将弹出一个新的弹窗，实时拉取该BID的账户列表，用户勾选后，点击保存，这些数据将是用户保存到系统中的已授权的账户列表。

注意：每个用户支持保存的账户数量需要进行控制，当达到上限时，需要提示用户，并告知用户删除账户后才能继续添加。具体可以保存的数量在服务端通过配置文件进行配置默认数值（当前为10），也支持按照用户匹配（可以写一张表，或者你认为其他的方案）

并排右侧有一个新增授权按钮，点击后向服务器发送请求，服务器返回一个授权链接，客户端使用浏览器打开授权链接，用户在浏览器中完成授权。服务端授权成功换到token后，先调用：

curl --location --request GET 'https://cm.bilibili.com/takumi/api/open_api/oauth2/userinfo' \
--header 'Authorization: Bearer access_token_参数'

将返回：{
    "message": "success",
    "code": 0,
    "data": {
        "bid": 11906268,
        "user_name": "雪雯11770V1"
    }
}

获取到该信息后，将token/refresh_token和BID和用户名的映射关系进行绑定，并告知客户端授权成功。（注意：1个用户可以进行多次授权，获取到多个token，需要进行区分）

完成授权后，客户端将自动刷新账户列表。

下方是账户列表，账户列表中每个账户包含账户名称、账户ID、操作按钮（删除），请用合适的表格组件来展示。

目前还在开发阶段，如果涉及到数据库变更的话，可以考虑清空数据库，不用担心现有数据受到影响。当前无需担心任何已有数据受到影响的问题。
